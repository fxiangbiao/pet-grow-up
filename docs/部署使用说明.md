## 一、整体拓扑（为什么要这样部署）

```
Windows（开发机）                    WSL2 / Ubuntu（运行 docker）
┌──────────────────────┐  rsync     ┌───────────────────────────────┐
│ 源码仓库 D:\ALAN\     │ ────────▶ │ /home/fxb_2/pet-grow-up       │
│  Codes\pet-grow-up    │  bash      │  docker compose (mysql/backend │
│  （Svelte/Spring/     │  petgrowup │  /frontend)                    │
│   Godot 客户端）      │  .sh sync  │  端口: mysql 3306 / api 8080    │
└──────────────────────┘            │        / web 3000              │
                                    └───────────────────────────────┘
```

- 代码在 **Windows 仓库**维护（git 也在那边）；Docker 只在 **WSL** 里（本机未装 Docker Desktop）。
- 部署 = `sync`（Windows→WSL 同步源码）→ `dev-up` / `prod-up`。
- Godot 客户端（孩子端）直接访问 `http://127.0.0.1:8080`（宿主映射），或离线模式无需后端。

## 二、环境前提（已具备，复查用）

| 位置 | 组件 | 说明 |
|------|------|------|
| WSL Ubuntu | docker 29.6.1 | `petgrowup.sh docker-up` 可拉起 daemon |
| WSL Ubuntu | JDK 17 + Maven 3.9.12 | 打包后端 JAR（pom `<java.version>17`，与容器 JRE17 一致） |
| WSL Ubuntu | Node 22 + npm 10 | 仅开发机侧可选构建用（容器内会自行 npm ci/build） |
| Windows | JDK 21 + Maven 3.9.16 | 本地跑后端（非 docker 方式）可选 |

> WSL 空闲默认会回收虚拟机，导致容器停摆。已在本机写入 `%UserProfile%\.wslconfig`
> （vmIdleTimeout=300000 等）；若仍频繁熄火，长期保持可用：
> `wsl -u root -e bash -lc "service docker start; docker start petgrowup-mysql"`

## 三、日常命令速查（在 WSL 或 Windows PowerShell 中均可）

```bash
# 推荐：Windows PowerShell 直接调 WSL 执行
wsl -u root -e bash /mnt/d/ALAN/Codes/pet-grow-up/petgrowup.sh <命令>

# 或在 WSL 内进入同步目录后执行
bash /home/fxb_2/pet-grow-up/petgrowup.sh <命令>
```

| 命令 | 作用 |
|------|------|
| `sync` | Windows 源码 → WSL 同步（排除 node_modules/target/.git/godot 缓存等） |
| `dev-up` | **开发栈**：打 JAR → 构建镜像 → 启动 mysql+backend+frontend |
| `dev-down` | 停止开发栈（数据卷保留） |
| `dev-restart backend` | 后端改代码后：重打 JAR + 重建镜像 + 重启 backend（**不要用**旧 `docker compose restart`，jar 是打进镜像的） |
| `dev-restart frontend` | 仅重启前端容器（dev 模式源码头挂载，改前端一般无需重启） |
| `prod-up` / `prod-down` | **生产栈**：`docker-compose.yml`（无热重载、镜像内 build） |
| `status` / `logs [backend\|frontend\|mysql]` | 看状态 / 跟踪日志 |
| `docker-up` | 幂等拉起 WSL docker daemon |

**首次部署一条龙（含今天代码）：**

```bash
wsl -u root -e bash -lc "service docker start"
wsl -u root -e bash /mnt/d/ALAN/Codes/pet-grow-up/petgrowup.sh sync
wsl -u root -e bash /mnt/d/ALAN/Codes/pet-grow-up/petgrowup.sh dev-up
```

- 前端（Svelte，admin 后台）: http://localhost:3000 — admin / admin123
- 后端 API: http://localhost:8080
- MySQL: localhost:3306，库 `petgrowup`，账号 `petuser/petpass123`（root 密码 `root123`）
- 首次启动自动执行 schema.sql + data.sql 建表播种（幂等，可反复启动）

## 四、Godot 客户端（孩子端 · 教/学/练/拓）

1. Godot 4.7 打开仓库 `godot/project.godot`（Windows 侧即可，无需 docker）。
2. F5 运行 → 主菜单：
   - **离线试玩**：内置示例数据，无需后端。
   - **登录**：连真实后端（默认 `http://127.0.0.1:8080`；用上面 dev-up 起的后端）。
     - 孩子账号：主菜单没有注册入口时，先用 HTTP 注册或让管理后台创建；

   归属 math_make_ten 节点，判答按缺加数）。

## 六、清理事项

- 旧脚本 `deploy.sh / dev.sh / restart.sh` 已并入 `petgrowup.sh` 删除；相关文档引用已更新。
- WSL 副本 `/home/fxb_2/pet-grow-up` 不含 `.git`（sync 排除），git 操作一律在 Windows 仓库进行。
- 若手工起过与 compose 同名的 `petgrowup-mysql` 容器，`dev-up` 会自动移除并交由 compose 重建。
- 数据库数据在 compose 命名卷 `mysql_data` 中；`dev-down` 不丢数据，想彻底重置：
  `docker compose -f docker-compose.dev.yml down -v`（会清空全部业务数据并重新播种）。
